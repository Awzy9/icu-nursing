# Medication reference library architecture (Phase 8)

A nursing reference for the 50 planned ICU medications (`content/drafts/medications/PLAN.csv`: 21 named in Part 7 of the master prompt, 8 antibiotics under "common ICU antibiotics", 21 proposed to reach 50). **It publishes no dose, concentration, infusion-rate, titration or compatibility instruction.** Nothing clinical is published; the only learner-visible entries are fictional synthetic agents in development mode.

## What is built (migration 0013, rollback in `supabase/rollback/0013_medications_down.sql`)
| Table | Purpose |
|---|---|
| `medication_items` | category (10), high-alert flag, localized name/class/summary, `sections` (12 fixed keys of localized lists), per-section support, evidence/licence status, evidence date, references, **regulator label source/version/date**, **jurisdiction note**, review/approval/publication metadata, and the reserved pharmacist columns |
| `medication_monitoring_items` | ordered nursing monitoring and safety checklist (observe / assess / laboratory / escalate / document) with critical flag and per-item support |
| `medication_revisions` | learner-visible revision history |
| `medication_bookmarks` | per-learner bookmarks |
Functions (SECURITY DEFINER, `auth.uid()`, learners have no table access): `md_list(query, category, bookmarked, high_alert)`, `md_get(code)`, `md_progress()`, `md_set_bookmark`. The catalogue test now covers 48 functions.

### The three safeguards
1. **Strict publication gate.** `private.medication_is_visible()` shows an entry only when published, not retired and either synthetic (labelled, fixtures on, development database) or clinical with a named approver, an independent `clinical_reviewer`, `evidence_status = supported`, `license_status` original/cleared and a label date. The publish guard also requires references, an evidence date, the label source/version/date and a jurisdiction note, the structure (3+ monitoring items; nursing responsibilities, safety alerts, escalation and the two institution sections), and freezes published content.
2. **No-dosing guard (database and files).** `private.medication_text_violation()` rejects any text containing a number with a unit (mg, mcg, units, mEq, mmol, mL, %), a rate expression (mcg/kg/min, mg/h), or the words titrate, dilute, reconstitute, compatible, y-site, loading dose, maintenance dose, infusion rate, bolus dose and mix with. It runs in a trigger on both content tables, so it holds for every writer including the owner role. The TypeScript twin (`src/lib/medications/no-dosing.ts`) is used by the fixture loader and the draft validator; tests prove they agree.
3. **Fixed separation of information levels.** Every entry has `general_pharmacology`, `administration_considerations`, `institution_preparation` and `institution_dosing` as separate sections; the last two are mandatory and are *always* referrals ("follow your pharmacy's preparation standard / the prescriber's order and your institution's protocol"), so the library never implies one universal concentration or protocol.

## Pharmacist-approval workflow: designed, not active
The owner has postponed review; nothing requires or activates a pharmacist. The design keeps the door open without risk:
* **Reserved columns now:** `pharmacist_reviewed_by`, `pharmacist_reviewed_at` (nullable, indexed, not read by the gate, not settable by any function; a test asserts none is ever set). The draft files carry `pharmacist_reviewed: false`, enforced by the validator.
* **Future steps (a later migration, not now):** (1) a `pharmacist` staff role with MFA; (2) a function `md_record_pharmacist_review(medication, outcome, notes)` writing an immutable row in a new `medication_pharmacist_reviews` table (reviewer, outcome, label version checked, jurisdiction, notes), refusing the author and requiring the label date; (3) the clinical-review gate adds "latest pharmacist review = approved for the same label version"; (4) any label update retires the approval; (5) if dose content is ever wanted, a separate `medication_dose_notes` table, absent today, that cannot be published without a pharmacist signature and an institution identifier (doses are always institution-specific).
* **Not done and not required:** recruiting reviewers, role creation, UI for reviewers.

## Drafting method (batches of up to 10)
All five batches (50 medications, `MD-01..50`, complete as unreviewed drafts): current FDA labels retrieved through the openFDA drug-label API (single-ingredient intravenous labels, latest effective date, repackagers excluded), recorded with set id, version, effective date and manufacturer in `LABEL_SOURCES.csv`. Only the boxed warning, indications, warnings/precautions, contraindications and adverse-reaction fields were used; dosing fields were not. Each statement is `sourced` (label text read in full for that field), `partial` (nursing inference, e.g. "escalate for..."), or `local_protocol`. **Jurisdiction:** US labels only; EMA, MHRA and SFDA labels were not read; practice guidelines and nursing sources were not read for these entries, so every draft is `partial` and none can pass the gate. `high_alert` is set only where a source read names the drug (the FDA infusion-pump page's examples: vasopressors, propofol, morphine); otherwise it is false with a note that the local list governs.
Batches 3-5 (sodium bicarbonate, eight antibiotics, phenylephrine, dopamine, nicardipine, labetalol, esmolol, nitroglycerin, furosemide, lorazepam, haloperidol, hydromorphone, naloxone, flumazenil, atropine, succinylcholine, enoxaparin, alteplase, tranexamic acid, levetiracetam, mannitol, pantoprazole, hydrocortisone) used the same method; each exact product, manufacturer, set id, version and effective date is in `LABEL_SOURCES.csv`. Product-specific labels are flagged in each row's jurisdiction/limits note (for example the intramuscular-only haloperidol label, premixed insulin, nitroglycerin in dextrose, Activase rather than Cathflo Activase, the haemophilia-only tranexamic acid label, the subcutaneous enoxaparin label). **Every draft records that a regulator label is not a bedside nursing practice guideline** (`evidence_type_note`, validator-enforced): the nursing actions are inferences from label warnings, marked partial, and a nursing or professional guideline was not read for any entry.
