# Phase 11 report (draft content only; nothing imported, published, merged or deployed)

Starting point: GitHub head `1394375` (one commit after `a260cd8`: the Android package is back to lowercase `com.criticalcarenursing.myapp` after the owner deleted the Play app that had required a capital C and created a new one with the lowercase name). The identifier was not changed in Phase 11.

## 1. Draft management (/admin/content)
* **Register** `/admin/content/register`: all 154 drafts (40 topics, 11 question sets, 25 skills, 50 medications, 20 scenarios as "cases", 8 equipment modules) with filters (type, evidence status, validation, worst licence class of cited sources, source freshness, workflow notes, text search), evidence and licence badges, source freshness warnings (stale after 180 days, or no verification date), validator feedback.
* **Draft page** `/admin/content/register/<key>`: validation messages, source table with licence class and verification age, snapshot history with a comparison of the latest two snapshots (evidence status, sources added/removed, gaps, sources still needed, validator issues), workflow notes with an append-only revision history shown as old/new.
* **Coverage dashboard** `/admin/content/coverage`: planned vs drafted, passing validators, with issues, reviewed, stale/undated sources, RED/unverified sources, evidence status.
* **Metadata, not content:** `src/content/draft-index.json` and `draft-history.json` are generated by `scripts/build-draft-index.ts` from the real validators and registers. They hold titles, ids, statuses, source ids, counts and content hashes only. Only admin code may import them (unit-tested); CI regenerates them and fails on a diff.
* **Staff-only editing infrastructure** (migration `0016_draft_workspace.sql`, manual rollback provided): workflow notes (owner, evidence, licensing, status) per draft key. No table access for anyone; three SECURITY DEFINER functions; reads need a staff role with MFA, writes need author/publisher/admin; clinical reviewers can read but not write; closed key pattern and field list; 1000-character cap; doses and rates refused by the same dose guard (written with PostgreSQL's `\y` word boundary after a test showed `\b` means backspace there); 40 changes per user per hour; every change audit-logged with lengths only; revision rows are append-only except that a deleted account detaches from them (`ON DELETE SET NULL`), so account deletion is never blocked.
* **Not enabled:** no approval, review, reviewer assignment or publication capability; nothing imports a draft file into any table (a DB test checks that no function or table touches roles, reviews or learner content and that no clinical row exists in any content table).
* **Tests:** `tests/db/draft-workspace.test.ts` (9), `tests/unit/admin-drafts.test.ts` (10), live isolated-stack UI tests (admin filters, validation, saves a note, dose refused, audit row, coverage accessibility; a learner is redirected).

## 2. Technical gaps
* **Scenario round trip:** independent-oracle test: 25 deterministic random walks per graph (14 real graphs plus the synthetic fixture) compared with a direct reading of the authored graph for next step, points, completion, scope counts, revisit positions, debrief and exactly what is revealed; and a field-by-field survival check of every authored option. Plus Phase 10's 26 tests.
* **Scenarios: 14 of 20 are decision graphs** (new: SC-08 acute seizure from NICE NG217 chapter 7). The six outlines left (SC-02, 05, 07, 09, 12, 16) have no adequate source read; see `docs/phase10/SCENARIO_EVIDENCE_GAPS.md`. Searches this phase found no open-access nursing-level source for postoperative haemorrhage (the nursing articles are paywalled).
* **Equipment parameter explanations:** two explanations written in EQ-01 where a source read says something about the parameter (continuous 3-lead ECG monitoring: UKKA and Resuscitation Council UK; pulse-oximeter accuracy caution: NICE CG103). The validator now requires sourced or partial support and listed sources for any explanation. All other parameters stay unexplained.
* New sources registered: N-NICE-NG217 (and N-NICE-CG103, N-NICE-NG232 from Phase 10); `LICENSING_REGISTER.md` updated. All limits remain visible in each draft's gaps and in the register.
